# Royal Exchange native UI

Scope: the shared frame/tabs, Contracts, Buy/Sell browsing and the sell order basket, following the supplied Royal Exchange UI brief. The user approved the Contracts appearance in live screenshots on 2026-09-30 and requested it as the basis for the remaining UI.

Minecraft 1.21.1, NeoForge 21.1.238, Java 21. Keep the existing `AbstractContainerScreen<RoyalExchangeMenu>` arrangement. Local mapped `MerchantScreen`, `CreativeModeInventoryScreen` and `AbstractButton` sources were inspected. Reuse runtime `widget/button*` and `container/villager/trade_arrow` sprites; item art, font and tooltips come from Minecraft and its active resource pack.

The 316 x 236 footprint fits the existing 320 x 240 minimum logical viewport. The shell uses stepped logical-pixel corners and vanilla highlight/shadow directions, compact attached tabs, a quiet title and textual feed status. No font shrinking, generated background image or web renderer.

Contracts replaces instruction cards with five selectable native-button rows per page, native 16-pixel item/reward previews in recessed 18-pixel wells, explicit quantities, expiry, one short instruction, local inventory readiness and server result feedback. Previous/next and wheel navigation retain access to larger lists. Full row descriptions and failure details remain available on hover; row buttons support standard keyboard focus and narration. Goods readiness is observational and does not guarantee fulfillment.

The menu appends 25 bounded display slots after the existing 94 slots. Existing slot indices, quote IDs, trade commands and fulfillment path remain unchanged. Item IDs and diamond rewards retain the short-slot wide-value codec. A new guarded row-selection command only changes selection; fulfillment continues through the existing explicit server action. Empty rows and selected details are cleared when contracts disappear. No polling or network calls were added to rendering.

Buy/Sell browsing uses a 7-column, 6-row grid of native 16-pixel items in recessed 18-pixel wells. Grid cells are focusable buttons with full item-name tooltips and narration. Wheel and native scrollbar navigation advance by grid rows, including the final partial row. Search, quantity entry, selected-item preview, diamond payment/reward preview, explicit quote request and confirmation remain separate controls. Exact owned inventory counts and remaining daily diamond allowance remain available. Empty inventory and empty search results have distinct messages. Tab follows the native widget focus path; quantity commit/cancel retains the existing 1-1024 bounds.

The sell basket is a 3 x 3 order preview, retaining the existing nine-good limit. Goods remain in player inventory until the existing explicit sale action. Each cell has separate edit/remove controls, quantity text and full tooltips. Every line below its server-provided minimum shows a red outline and an explicit minimum quantity. Ready, pending, expired and failed quotes remain distinct; totals appear only for ready quotes. No inventory deposit or drag behavior was introduced.

Native frame colors, slot wells and runtime widget sprites replace the former cream cards and flat buttons throughout. Existing config keys remain registered for compatibility; card/button palette keys and removed instruction-card offsets no longer affect native surfaces. Existing text offsets and semantic status colors remain where applicable.

The conservative polish pass retains the existing frame, attached tabs, grids, item previews, widget bounds and transaction actions. A nine-pixel line-art crown adds restrained title identity. The configured muted green accent is shared by selected tabs/cells/contract rows, selected-item markers, ready actions and connected/success states. Vanilla item-decoration rendering keeps owned counts above item models, with exact aggregated counts still available in the selected-item text and tooltips. The scrollbar now ends at the bottom of the grid. Contract quantities and rewards are centered under their wells, with secondary row text quieter than the item name.

Sell's remaining daily diamond payout is grouped below available inventory and order review, away from the quantity heading. Nothing selected, no eligible inventory, no search results, insufficient owned quantities and empty baskets have compact distinct messages. Final action buttons remain visible but disabled until their existing conditions permit activation; their activation rules and commands are retained. Empty basket cells use gray recessed preview wells. Goods remain in inventory and cannot be deposited into these cells.

Build candidate: `0.29.7-ui-preview`, passed as a Gradle property. `0.29.6-ui-preview` was installed on 2026-09-30 with its prior JAR backed up. This polish changes only the client screen, layout constants, English UI text and this design note. No menu, economy, inventory, networking or connectivity implementation changes. Verification uses 120 unit tests and paired actual Minecraft framebuffer fixtures at GUI Scale 6 (2560 x 1440), plus the 320 x 240 minimum logical viewport and isolated input/disabled-state checks. Fixtures do not load a world or exercise server transactions. Live server synchronization, trades, fulfillment and custom resource-pack behavior remain unverified. Stop before installation pending the user's installation request.
